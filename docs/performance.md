# 性能表现

> 说明：本文只陈述 Magisk Pro 在真实实现中带来的**结构性优化方向**，不夸大具体数字。所有改进点均可从源码复现验证。

## 结构性优化

### DoH 缩短 DNS 解析链路

传统 App 的 DNS 请求可能经过运营商递归服务器，存在多级转发延迟与缓存不一致问题。Pro 的 `DnsResolver` 直连公共 DoH 服务（Cloudflare / Google / AdGuard），**减少递归跳数**，在同一网络环境下通常能获得更稳定的解析耗时。

- 同一服务商下复用 `dohCache`，避免重复握手。
- 切换服务商才重建缓存，日常使用零开销。

### tmpfs 精简挂载减少根目录扰动

上游在 `rw-root` 场景会在 `/sbin` 重建符号链接树。Pro 将挂载点迁移到 `/debug_ramdisk` 并移除 `recreate_sbin`：

- **减少文件系统操作**：不再逐项重建 `/sbin` 符号链接。
- **目录结构更贴近 AOSP 默认布局**，降低对依赖路径探测的第三方工具的干扰。
- 挂载点本身仍是 tmpfs（内存盘），读写性能与上游一致。

### Pro Hide 降低检测暴露面

随机化的进程名使外部工具无法通过固定进程名命中 `magiskd`，从**对抗层面**减少被检测与干扰的可能，进而避免由此引发的重装/清理等运维开销。进程伪装本身不消耗额外资源。

### 权限组注入避免多余提权开销

su 请求按策略注入 `system` / `shell` 身份时，**无需完整切换到 root 域**，降低了不必要的权限提升范围（最小权限原则），减少潜在审计噪音。

## 实测建议

具体延迟与耗电数据受设备、内核与网络环境影响较大，建议在**同一设备、同一网络**下对比上游 Magisk 与 Magisk Pro 进行 A/B 测试。

| 对比维度 | 说明 |
|---|---|
| DNS 解析耗时 | 用 `dig` / `nslookup` 对比系统 DNS 与 DoH |
| 挂载布局 | `mount` 查看 `/debug_ramdisk` 与 `/sbin` |
| 进程名 | `ps -A` / `cat /proc/<pid>/comm` 观察 magiskd 随机名 |
| 授权路径 | 对比 su 请求时的 SELinux 上下文 |
